# 本机删除与昵称展示：验收记录

日期：2026-11-15。此记录针对 V1 冻结之后的本次改动，V1.0.0 原标签保持不变。

## 本次改动

- 创建图文、账号管理、私信来源、发布记录等位置以已核验的平台昵称为主、系统别名为辅；未核验昵称的账号提示先检查。
- 私信单条消息和整个会话可经二次确认后在本机软删除。快速和完整同步会遵守删除记录；核验到删除后的新消息时，会话才重新出现。
- 同一平台账号的多个别名共享删除记录。另一个别名有尚未核对的消息时，整个会话删除会被阻止。
- 时间或顺序无法可靠确认的消息保守处理，并使同步结果提示需要核对。软删除并非安全擦除，小红书原会话及旧备份不受影响；恢复旧备份可能恢复当时的本机显示状态。
- 老版工作台进程继续运行时，页面隐藏新版删除入口并提示需要重启，避免出现无法使用的按钮。

## 已验证

- 172 项 Python 回归通过，包括发布、账号、私信、恢复保护、浏览器队列、备份、MCP 及删除同步边界；前端脚本语法与提醒检查通过。随后加入的旧进程兼容保护单独通过了浏览器界面回归及前端检查；重复别名的 MCP 边界和新 MCP 进程的删除过滤各自通过独立测试。
- 使用独立的虚拟账号、消息和数据库，以真实浏览器检查过昵称与别名、图标、确认提示、取消与确认删除、刷新后的持久性、删除后新消息以及窄屏布局。
- 真实业务数据库的完整性检查为 `ok`；原有账号、发布批次及私信保留。升级前创建了经过校验的本机数据库备份。
- 新版工作台已启动。升级前后数据库的账号、批次、任务、会话和消息数量一致；实际页面确认账号显示平台昵称及别名，部分历史仍提示需要核对。
- 本轮没有发布作品、发送私信或删除真实客户消息；删除和同步边界测试均使用隔离数据或模拟平台响应，不能当作小红书真实来信的现场验收。

## 尚待处理

- 使用 MCP 的旧 Codex 会话运行着旧代码；需要重新打开会话以启用新版删除过滤。在旧进程退出前，不要依赖它隐藏已删除内容。
- 同一平台账号的多个别名同时同步同一会话时，原有 MCP 稳定会话键无法唯一定位并会拒绝查询；隔离测试确认可改用数字会话 ID。该限制未在本次改动中扩展。

## 后续批量删除验收

- 会话可逐个勾选或全选当前筛选结果，消息可逐个勾选或全选已同步的本机消息；全选包括尚未加载到页面的数据，删除前需要确认数量。
- 删除使用本机快照和事务；所选会话出现新变化时整批停止，浏览器任务运行时须等待结束。删除不影响平台原会话，旧备份可能包含删除前的数据。
- 185 项回归通过；隔离数据的真实浏览器测试覆盖跨页全选、取消确认、批量删除和窄屏，另验证一次处理 1200 条消息。新版工作台入口已在真实环境检查，未用真实客户消息做删除测试。
